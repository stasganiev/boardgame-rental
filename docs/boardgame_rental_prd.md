# PRD — Платформа аренды настольных игр

> **Версия:** 2.0
> **Дата:** Март 2026
> **Статус:** Актуальный

---

## 1. Обзор приложения и цели

### Описание продукта
Веб-платформа для аренды настольных игр, соединяющая владельцев игр с людьми, желающими в них поиграть. Работает по модели бесплатного маркетплейса объявлений (аналог Авито), где владельцы выставляют свои игры на аренду, а арендаторы выбирают и бронируют их. Связь между сторонами происходит напрямую через внешние каналы (телефон, Telegram, WhatsApp, email).

### Основная бизнес-цель
Создать бесплатную открытую платформу, снижающую барьер для аренды настольных игр. Платформа полностью бесплатна для всех пользователей — без комиссий, без платежей внутри системы.

### Ключевые принципы MVP
- Простота использования
- Прямая связь между пользователями через внешние каналы
- Модерируемое качество контента
- Геолокация: поиск игр рядом с тобой
- Многоязычность: интерфейс на русском и английском
- Полностью бесплатный стек технологий

## 3. Основные функции и функциональность

### 3.1 Система пользователей

#### Регистрация и авторизация
**Технические требования:**
- Поля регистрации: email (string, unique), пароль (string, min 8 символов), имя (string), страна (string), город (string)
- Подтверждение email при регистрации
- Двухфакторная аутентификация — только через email (одноразовый код)
- JWT-токены для управления сессиями (Supabase Auth)
- Автоматическое определение города при регистрации (по IP или геолокации браузера)
- Выбор языка интерфейса при регистрации (EN / RU), сохраняется в профиле

**Критерии приемки:**
- Пользователи могут регистрироваться с подтверждением email
- Система поддерживает вход/выход с сохранением сессии
- Доступно восстановление пароля через email
- Реализована двухфакторная аутентификация через email

#### Профили пользователей
**Поля профиля:**
```javascript
User = {
  id: String (UUID),
  email: String (unique),
  name: String,
  avatarUrl: String, // Supabase Storage URL
  country: String,
  city: String,
  location: {
    lat: Number,
    lng: Number,
    city: String,
    country: String
  },
  contact: {
    type: Enum["phone", "telegram", "whatsapp", "email", "other"],
    value: String,       // номер/username/адрес
    isPublic: Boolean    // виден ли контакт другим пользователям
  },
  rating: Number,        // 0-5, вычисляется автоматически
  dealsCount: Integer,
  userType: Enum["owner", "renter", "both"],
  language: Enum["en", "ru"], // предпочтительный язык интерфейса
  notificationSettings: {
    emailOnBookingRequest: Boolean,
    emailOnBookingConfirmed: Boolean,
    emailOnBookingCancelled: Boolean
  },
  createdAt: Date
}
```

**Контакт для связи:** пользователь сам указывает удобный способ коммуникации. Контакт отображается арендатору после подтверждения брони владельцем (если `isPublic: false`) или всегда (если `isPublic: true`). Встроенного чата на платформе нет — стороны общаются напрямую.

### 3.2 Управление играми

#### База данных игр (номенклатура)
**Модель данных игры:**
```javascript
Game = {
  id: String (UUID),
  name: String (required),
  minPlayers: Integer,
  maxPlayers: Integer,
  minAge: Integer,
  gameDuration: String,         // "30-60 минут"
  complexity: Integer (1-5),
  genre: Array[String],
  weight: Number,               // в кг
  description: Text,
  officialPhotos: Array[String], // URLs из Supabase Storage
  createdBy: String (userId),
  moderationStatus: Enum["pending", "approved", "rejected"],
  createdAt: Date
}
```

#### Экземпляры игр владельцев
**Модель данных экземпляра:**
```javascript
GameInstance = {
  id: String (UUID),
  gameId: String (ref Game),
  ownerId: String (ref User),
  condition: Enum["новая", "отличная", "хорошая", "удовлетворительная"],
  ownerPhotos: Array[String],   // фото конкретного экземпляра (Supabase Storage)
  pricePerDay: Number,          // стоимость аренды в день (ориентировочно, для договорённости)
  location: {
    lat: Number,
    lng: Number,
    city: String,
    country: String
  },
  availabilityRules: {
    daysOfWeek: Array[Integer], // 0-6, где 0 - воскресенье
    minRentalDays: Integer,
    maxRentalDays: Integer
  },
  additionalDescription: Text,
  isActive: Boolean,
  createdAt: Date
}
```

> **Примечание:** Поля `depositAmount` и `serviceAreas` удалены. Местоположение объявления хранится в `location` с координатами для геопоиска.

#### Геопоиск по радиусу
- Поиск игр по радиусу (в км) от координат пользователя или указанной точки на карте
- Расчёт расстояния через формулу Haversine (без внешних API)
- Главная страница показывает интерактивную карту с пинами доступных объявлений
- Карта реализована через OpenStreetMap + Leaflet.js (полностью бесплатно, без API-ключей)

#### Календарь доступности
**Модель данных:**
```javascript
Availability = {
  id: String (UUID),
  gameInstanceId: String (ref GameInstance),
  date: Date,
  status: Enum["available", "booked", "blocked"]
}
```

### 3.3 Система бронирования

#### Процесс бронирования
**Модель брони:**
```javascript
Booking = {
  id: String (UUID),
  gameInstanceId: String (ref GameInstance),
  renterId: String (ref User),
  ownerId: String (ref User),
  startDate: Date,
  endDate: Date,
  status: Enum["pending", "confirmed", "in_progress", "completed", "cancelled"],
  message: Text,             // сообщение от арендатора при запросе
  createdAt: Date,
  confirmedAt: Date
}
```

> **Примечание:** Поля `totalAmount`, `depositAmount`, `platformFee`, `paymentStatus` удалены — платформа не участвует в финансовых расчётах. Договорённость о цене и оплате происходит между пользователями напрямую.

**Критерии приемки:**
- Арендатор выбирает игру и даты, оставляет сообщение
- Владелец получает email-уведомление о новом запросе
- Владелец подтверждает или отклоняет бронь
- После подтверждения арендатору становится виден контакт владельца для дальнейшей договорённости
- Стороны договариваются об условиях и оплате напрямую через внешние каналы

---

### 3.4 Система рейтингов и отзывов

#### Взаимные отзывы
**Модель отзыва:**
```javascript
Review = {
  id: String (UUID),
  bookingId: String (ref Booking),
  reviewerId: String (ref User),
  revieweeId: String (ref User),
  rating: Integer (1-5),
  comment: Text,
  type: Enum["owner_to_renter", "renter_to_owner"],
  createdAt: Date
}
```

**Критерии приемки:**
- Отзывы доступны только после завершения сделки (статус `completed`)
- Взаимные оценки: владельцы оценивают арендаторов, арендаторы — владельцев
- Общий рейтинг пользователя рассчитывается автоматически как среднее

## 4. Технический стек (полностью бесплатный)

### Frontend & Web Hosting

| Технология | Назначение |
|---|---|
| **Next.js 14 (App Router) + TypeScript** | Основной веб-фреймворк (заменяет React CRA) |
| **Tailwind CSS** | Стилизация (заменяет Material-UI / Ant Design) |
| **Zustand** | State management |
| **React Hook Form + Zod** | Формы и валидация |
| **Leaflet.js + React-Leaflet** | Карты на базе OpenStreetMap (бесплатно, без API-ключей) |
| **next-i18next** | Интернационализация (i18n) |
| **Vercel** | Хостинг (бесплатный план) |

### Backend & Database (BaaS — Supabase)

**Supabase** заменяет весь серверный стек: Node.js/Express, PostgreSQL, Redis, Prisma, Passport.js, Cloudinary, Railway/Render.

| Компонент Supabase | Назначение |
|---|---|
| **Supabase Auth** | JWT, подтверждение email, 2FA через email |
| **Supabase Database** | PostgreSQL с Row Level Security (RLS) |
| **Supabase Storage** | Изображения игр, фото профилей |
| **Supabase Edge Functions** | Серверная бизнес-логика (TypeScript/Deno) |

**Бесплатный план Supabase:** 500 МБ БД, 1 ГБ хранилище, 2 ГБ трафик/месяц.

### Email

**Resend** — бесплатно до 3 000 писем/месяц (заменяет SendGrid/Twilio).

Используется для:
- Подтверждения email при регистрации
- Двухфакторной аутентификации (OTP-код)
- Уведомлений о бронировании
- Восстановления пароля

### Мобильное приложение (фаза 2)

| Технология | Назначение |
|---|---|
| **React Native + Expo** | Кросс-платформенное мобильное приложение |
| **Expo Go** | Разработка и тестирование |
| **EAS Build** | Сборка для App Store / Google Play |

Мобильное приложение использует тот же Supabase backend, что и веб-версия.

### Убранные технологии

Следующие компоненты исключены из стека:
- Node.js/Express → заменён Supabase Edge Functions
- Redis → заменён встроенным кешированием Supabase
- Prisma → заменён Supabase client
- Passport.js → заменён Supabase Auth
- Twilio → убран (SMS 2FA не используется)
- Railway/Render → заменён Supabase
- Cloudinary → заменён Supabase Storage
- Stripe, PayPal → убраны полностью (платёжной системы нет)

## 5. Интернационализация (i18n)

### Языки MVP
- **EN** — английский
- **RU** — русский

### Архитектура i18n
- Библиотека: **next-i18next** (поверх i18next)
- Маршрутизация по локали: `/[locale]/...` (App Router Next.js 14)
- Файлы локализации:
  ```
  /locales
  ├── /en
  │   ├── common.json
  │   ├── auth.json
  │   ├── games.json
  │   └── bookings.json
  └── /ru
      ├── common.json
      ├── auth.json
      ├── games.json
      └── bookings.json
  ```
- Добавление нового языка требует только создания новой папки с переводами и регистрации кода локали в конфиге — без изменений в коде компонентов
- Язык по умолчанию определяется настройками браузера, сохраняется в профиле пользователя

### Правила i18n
- Все строки UI выносятся в файлы локализации — хардкода текста в компонентах нет
- Форматирование дат, чисел, валют через `Intl` API (нативно, без доп. библиотек)
- Направление текста: LTR для EN и RU (RTL-языки — фаза 2 при добавлении арабского/иврита)

## 6. Концептуальная модель данных

### Основные сущности и связи
```
User (1) ←→ (M) GameInstance
User (1) ←→ (M) Booking (as renter)
User (1) ←→ (M) Booking (as owner)
Game (1) ←→ (M) GameInstance
GameInstance (1) ←→ (M) Availability
GameInstance (1) ←→ (M) Booking
Booking (1) ←→ (2) Review
```

### Индексы для производительности
- Users: email, city, location (PostGIS GIST index для геопоиска)
- Games: name, genre
- GameInstances: gameId, ownerId, isActive, location (GIST)
- Bookings: renterId, ownerId, status, startDate
- Availability: gameInstanceId, date, status

### Row Level Security (Supabase RLS)
Большинство CRUD-операций выполняются напрямую через Supabase client с политиками RLS:
- Владелец может редактировать только свои `GameInstance`
- Пользователь видит только свои `Booking`
- `Review` можно создать только после `Booking` со статусом `completed`
- Edge Functions используются только для сложной логики: геопоиск с Haversine, агрегация рейтингов, отправка писем через Resend

## 8. Аспекты безопасности

### Аутентификация и авторизация
- Хеширование паролей (bcrypt, управляется Supabase Auth)
- JWT токены с коротким временем жизни + refresh токены
- 2FA только через email (OTP-код, без SMS, без Twilio)
- Rate limiting на уровне Supabase и Edge Functions

### Защита данных
- Валидация всех входных данных (Zod на фронтенде + RLS на уровне БД)
- SQL injection защита через Supabase client (parameterized queries)
- XSS защита через CSP headers (Next.js)
- HTTPS везде (Vercel обеспечивает автоматически)
- Приватный контакт пользователя (`isPublic: false`) не передаётся до подтверждения брони

### Конфиденциальность геоданных
- Точные координаты пользователей не отображаются публично
- На карте объявления показываются с погрешностью (округление до ~500м)
- Пользователь может скрыть геолокацию и указать только город

### API — структура с учётом Supabase

Большинство операций выполняются напрямую через **Supabase client + RLS** без кастомного API. Edge Functions задействуются только там, где нужна серверная логика.

**Supabase client (прямые запросы):**
```
Auth:
supabase.auth.signUp()
supabase.auth.signIn()
supabase.auth.signOut()
supabase.auth.resetPasswordForEmail()

Users/Profiles:
supabase.from('users').select() / .update()

Games:
supabase.from('games').select() / .insert() / .update()

Game Instances:
supabase.from('game_instances').select() / .insert() / .update() / .delete()

Bookings:
supabase.from('bookings').select() / .insert() / .update()

Reviews:
supabase.from('reviews').select() / .insert()
```

**Edge Functions (сложная логика):**
```
POST /functions/v1/geo-search
  body: { lat, lng, radiusKm, filters }
  → возвращает game_instances в радиусе

POST /functions/v1/send-email
  body: { type, recipientId, bookingId }
  → отправляет письмо через Resend

POST /functions/v1/update-rating
  body: { userId }
  → пересчитывает средний рейтинг пользователя

Admin (только для модераторов):
POST /functions/v1/moderate-game
  body: { gameId, status, reason }
```

> **Платёжных endpoints нет** — платформа не участвует в финансовых операциях.

## 12. Система администрирования

### Функции админ-панели

**Управление контентом:**
- Модерация очереди новых игр (approve / reject с указанием причины)
- Редактирование/удаление некорректных объявлений
- Управление пользователями (блокировка, разблокировка)

**Модерация:**
- Очередь на модерацию новых игр
- Система жалоб пользователей
- Управление спорными ситуациями

**Системные настройки:**
```javascript
PlatformSettings = {
  maxRentalDays: Integer,        // максимальный срок аренды
  autoModerationEnabled: Boolean, // автоматическая модерация по алгоритму
  supportedLanguages: Array[String], // ["en", "ru"]
  defaultSearchRadiusKm: Integer  // радиус поиска по умолчанию
}
```

> **Примечание:** Финансовые настройки (commissionRate, методы оплаты, валюты) удалены — платформа не участвует в расчётах.

## 14. Потенциальные проблемы и их решения

### Техническая масштабируемость
**Проблема:** Рост с 100 до 100 000 пользователей
**Решение:**
- Supabase автоматически масштабирует PostgreSQL
- Vercel Edge Network для глобальной доставки контента
- Кеширование геопоиска (результаты запроса с теми же параметрами)
- CDN для статических ресурсов (Vercel встроенный)

### Качество контента
**Проблема:** Дублирование игр, некачественные описания
**Решение:**
- Обязательная модерация новых игр
- Алгоритм поиска дублей по названию (нечёткое сравнение строк)
- Система жалоб пользователей
- Рейтинговая система качества объявлений

### Доверие между пользователями
**Проблема:** Споры между пользователями, повреждение игр
**Решение:**
- Обязательные фото до и после аренды (через Supabase Storage)
- Система взаимных отзывов с историей сделок
- Детальные правила и условия использования платформы
- Служба поддержки для разрешения споров

### Проблема холодного старта
**Проблема:** Мало игр и пользователей на старте
**Решение:**
- Партнёрство с магазинами настольных игр
- Реферальная программа
- Продвижение в игровых сообществах (ВКонтакте, Telegram-каналы, BoardGameGeek)
- Заполнение базы игр из открытых источников (BoardGameGeek API) перед запуском

### Конфиденциальность контакта
**Проблема:** Нежелательный контакт, спам
**Решение:**
- Контакт владельца открывается только после подтверждённой брони
- Пользователь сам выбирает тип контакта и его видимость (`isPublic`)
- Возможность пожаловаться на пользователя в администрацию
